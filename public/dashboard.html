How Authentication Works


    

      

        Session Auth: After successful login + MFA, the server creates a session
        (secureid.sid httpOnly cookie). Every request sends this cookie automatically.
        /api/me reads the session, looks up the user in the store, and returns the profile.
      

      

        JWT Auth: POST /api/token issues a short-lived (15 min) JWT
        signed with JWT_SECRET. The client sends it as
        Authorization: Bearer <token>. The server verifies the signature before
        granting access to /api/protected.
      

      

        Logout: POST /api/logout adds the JWT to a revoked-token set,
        destroys the server-side session, and clears both cookies. After logout,
        /api/me returns 401.
      

      

        OTP: Generated with crypto.randomInt, hashed with bcrypt,
        stored as a challenge. Printed to server console (simulated email/SMS). Single-use,
        5-minute expiry, 3 attempt limit.
